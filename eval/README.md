# eval

วัดผลระบบด้วยชุดคำถาม 40 ข้อ (`questions.json`) ทุกครั้งที่ปรับอะไร ให้รันใหม่แล้วเทียบตัวเลข แทนการลองถามทีละข้อแล้วดูด้วยตา

## วัดอะไรบ้าง

| ตัวชี้วัด | ความหมาย |
|---|---|
| Hit@1 / Hit@3 / Hit@5 | ร้อยละของคำถามที่การค้นหาเจอหน้าที่ถูกใน 1 / 3 / 5 อันดับแรก |
| MRR | ค่าเฉลี่ยของ 1/อันดับที่เจอหน้าที่ถูก (1.0 = อันดับ 1 ทุกข้อ) |
| ตอบถูกทั้งหมด | ข้อที่มีคำตอบ: ตอบ + มีข้อมูลสำคัญครบ + อ้างอิงถูกหน้า, ข้อที่ไม่มีคำตอบ: ตอบว่าไม่พบ |
| ตอบ ไม่ปฏิเสธ | ข้อที่เอกสารมีคำตอบ แต่ AI ตอบว่าไม่พบ จะทำให้ค่านี้ลด |
| มีข้อมูลสำคัญครบ | คำตอบมีคำใน `must_include` ครบ เช่น "22" หรือ "1.50" |
| อ้างอิงถูกหน้า | มีอ้างอิงอย่างน้อย 1 ชิ้นที่มาจากหน้าที่ถูก |
| อ้างอิงทั้งหมดที่ถูกหน้า | จากอ้างอิงทั้งหมด กี่เปอร์เซ็นต์ที่มาจากหน้าที่ถูก (ต่ำ = อ้างอิงมั่ว) |
| ตอบว่าไม่พบ | ข้อที่เอกสารไม่มีคำตอบ AI ต้องตอบว่าไม่พบ (ต่ำ = แต่งคำตอบ) |

## รัน

1. เปิดครบทั้ง 4 ส่วน (Docker, model service, backend, frontend ไม่จำเป็น)
2. ในระบบควรมีแค่ `sample-docs/sample-regulation-th.pdf` ไฟล์เดียว ถ้ามีเอกสารอื่นด้วย ผลการค้นจะเปลี่ยน
3. ที่ `D:\ThaiDocRAG`:

```powershell
py eval\run_eval.py
```

ไม่ต้องตั้งชื่อรอบเอง ตัวรันจะถาม backend ว่าใช้ค่าอะไรอยู่ แล้วตั้งชื่อให้ เช่น `plain-k5-v2` (รูปแบบ chunk, จำนวนชิ้น, รุ่นของ prompt) จะได้ไม่สับสนว่าไฟล์ไหนเป็นการทดลองอะไร

ใช้เวลาราว 3–4 นาที (เรียก LLM 40 ครั้ง) ไม่ต้องติดตั้งอะไรเพิ่ม ใช้แค่ไลบรารีมาตรฐานของ Python 3.10 ขึ้นไป

ตัวเลือกอื่น:

```powershell
py eval\run_eval.py --label search-only --no-chat     # วัดเฉพาะการค้น ไม่กี่วินาที
py eval\run_eval.py --label try --only q11,q12        # รันเฉพาะบางข้อ
```

ผลลัพธ์อยู่ที่ `eval/results/<วันเวลา>_<label>.md` (อ่านง่าย) และ `.json` (ใช้เทียบ) commit เก็บไว้ได้เลย เป็นหลักฐานว่าปรับแล้วดีขึ้นแค่ไหน

## ทดลองปรับ

ค่าที่ปรับได้โดยไม่แก้โค้ด อยู่ใน `rag-backend/.env` (แก้แล้วรีสตาร์ต backend):

| ค่า | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `CHAT_TOP_K` | 5 | จำนวน chunk ที่ส่งให้ AI อ่าน |
| `CHAT_MIN_SCORE` | 0.35 | chunk ที่คะแนนต่ำกว่านี้ไม่ส่งให้ AI |
| `CHAT_SOURCE_FORMAT` | plain | `plain` = `[S1] ไฟล์: … หน้า …`, `tagged` = ครอบด้วย `<source id="S1" …>` |
| `CHAT_VERIFY_CITATIONS` | true | ตรวจว่าแต่ละประโยคตรงกับชิ้นไหนจริง แล้วแก้เลขอ้างอิงที่ผิดหรือขาด (ชื่อรอบจะมี `-cv`) |

ตัวอย่าง: ลอง tagged แล้วเทียบกับ baseline

```powershell
# 1. ใส่ CHAT_SOURCE_FORMAT=tagged ใน rag-backend\.env แล้วรีสตาร์ต backend
py eval\run_eval.py
py eval\compare.py eval\results\<ไฟล์รอบก่อน>.json eval\results\<ไฟล์รอบนี้>.json
```

`compare.py` บอกว่าตัวชี้วัดเปลี่ยนเท่าไร และข้อไหน "แก้ได้" หรือ "พังลง"

## ข้อควรรู้

- **LLM ตอบไม่เหมือนเดิมทุกครั้ง:** ต่างกัน 1–2 ข้ออาจเป็นแค่ความบังเอิญ ถ้าจะสรุปว่าแบบไหนดีกว่า ให้รันแต่ละแบบ 2 รอบ
- **การตรวจ "ข้อมูลครบ" ใช้การหาคำ:** ถ้าคำตอบถูกแต่ใช้คำต่างไป (เช่น เขียน "สองภาค" แทน "2 ภาค") อาจนับผิดได้ ให้ดูส่วน "ข้อที่ผิด" ในไฟล์ `.md` ทุกครั้ง แล้วเพิ่มคำที่ใช้แทนกันได้ใน `must_include` ด้วย `|`
- **แก้ `SYSTEM_PROMPT` แล้วต้องเพิ่ม `PROMPT_VERSION`** ใน `PromptBuilder.java` ไม่อย่างนั้นผลสองรอบจะดูเหมือนใช้ prompt เดียวกัน
- **อย่าแก้ prompt ให้เข้ากับคำถามในชุดนี้โดยตรง:** เช่น อย่าใส่คำว่า "รีไทร์" ลงใน prompt ตัวเลขจะดูดีแต่ใช้กับคำถามจริงไม่ได้
